## 1. 背景与问题

多个 Rust 产品需要向浏览器、桌面端或其他服务提供 HTTP API、SSE 进度流和 WebSocket 双向通道。目前各产品重复处理监听、TLS、资源限额、长连接退出和日志隐私，容易产生不同的安全与运行行为。VibeCAD 的 Prompt/Agent 场景是一个代表性消费者，但公共库不应绑定 Agent、CAD 或特定应用协议。

`rs-web` 面向编写 Rust 服务的开发者，提供基于 Axum 的 RESTful MVC 风格声明式路由及可组合服务端基础设施。应用可以用少量属性宏声明 Controller、路径前缀和 HTTP 方法，也可以直接使用 Axum Router；应用继续拥有状态、认证和业务语义。

## 2. 目标、非目标与发布范围

### 2.1 首版目标

| 编号 | 目标 | 成功证据 |
| --- | --- | --- |
| G1 | 同一应用 Router 在显式 HTTP 或 HTTPS 监听上运行；HTTPS 路由可升级 WSS | 本地端到端测试与示例 |
| G2 | 不可信输入和长连接占用均有有限上界 | 逐项边界、超限及慢消费者测试 |
| G3 | SSE/WS 能感知断开并在服务关闭时有界退出，不误伤普通 API | 取消、并发与停止测试 |
| G4 | 保留 Axum 的 Router、State、extractor、middleware、Sse 与 WebSocketUpgrade 使用方式 | 两个独立消费者示例，无容器或宏注册 |
| G5 | 基础设施错误可识别，默认诊断不泄露敏感数据 | 错误矩阵、TRACE 隐私测试 |
| G6 | 用属性宏声明 REST Controller 和 HTTP 方法，无需手写每个 `Router::route` | 独立消费者示例、编译失败测试与实际 HTTP 请求 |

### 2.2 非目标

首版不提供 Agent 工作流、任务存储、事件重放、业务幂等、JSON-RPC/CIP、Socket.IO、认证服务、OpenAPI、静态资源、文件上传策略、证书签发/续期、反向代理、HTTP 客户端或自动重试。应用可以自行使用 Axum/Tower 组件补足这些能力。

### 2.3 使用边界

- `rs-http` 继续提供出站 HTTP 客户端；`rs-web` 不依赖它。
- 直接公网部署必须配置可信 TLS；若在可信反向代理后使用 HTTP，代理的信任和转发头解析由应用显式配置。库默认不信任 `Forwarded` 与 `X-Forwarded-*`。
- 库不替应用做认证、授权、Origin 策略选择、任务取消或业务 ACK。服务端关闭连接也不意味着已受理的业务任务被取消。

## 3. 用户与核心使用场景

| 角色 | 任务 | 期望 |
| --- | --- | --- |
| 服务开发者 | 将已有 Axum Router 投入服务 | 明确绑定地址、取得实际端口、选择 HTTP/HTTPS、得到可识别启动错误 |
| API 开发者 | 定义一组 REST 资源接口 | 在 Controller 和方法上写路径、HTTP 动词标记，保留 Rust 类型检查和 Axum 提取器 |
| 应用开发者 | 提供受限 JSON API | 对字节量和 JSON 结构设置预算，越限行为稳定，保持原生 extractor 可用 |
| 流式 API 开发者 | 发送 SSE 进度或承载 WS 双向消息 | 连接、队列、大小、空闲和退出都可控；业务事件仍由应用定义 |
| 运维人员 | 停止服务并排查失败 | 停止有期限，能区分正常退出与强制关闭，日志默认保护凭据与内容 |

代表性用户旅程：开发者用宏定义 Controller 及其 `impl` 方法 → 装配 Router → 配置地址、限额及可选 TLS → 绑定并取得实际地址 → 提供服务 → 请求经限额与应用中间件处理 → SSE/WS 使用独立长连接策略 → 宿主触发 shutdown → 服务停止接受新连接并结束会话 → 调用方得到停止报告。

## 4. 功能需求

下表中的 **P0** 为首版交付要求；**P1** 为首版可选能力，但启用对应 feature 时仍需满足验收条件。编号用于设计追踪和测试。

### 4.1 启动、监听与 TLS

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-SRV-01 | P0 | 接受调用方构建完毕的 Axum `Router<()>`；不自动注册或改写业务路由 | State、middleware、404 行为与直接使用 Axum 一致 |
| R-SRV-02 | P0 | HTTP 绑定必须由调用方显式给出 SocketAddr；绑定成功后可取得实际地址 | `127.0.0.1:0` 返回非零监听端口；端口占用返回绑定错误 |
| R-SRV-03 | P1 | `tls-rustls` 开启后提供 HTTPS 绑定，使用同一 Router；证书/密钥无法加载或不匹配时在提供服务前失败 | HTTPS 和 WSS 可连接，明文不能作为 HTTPS 使用；错误不包含私钥 |
| R-SRV-04 | P0 | 调用方控制生命周期，不安装进程信号处理器；停止有确定期限 | 外部 shutdown 信号可触发，超期连接被终止并报告 |
| R-SRV-05 | P0 | 配置在绑定前校验，非法的零值/相互冲突的限额须明确报错 | 非法配置不会部分启动服务 |

### 4.2 REST Controller 与声明式路由

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-MVC-01 | P0 | 提供 `#[rest_controller("/prefix")]` 用于 `impl` 块；方法使用 `#[get_mapping]`、`#[post_mapping]`、`#[put_mapping]`、`#[patch_mapping]`、`#[delete_mapping]` 声明相对路径，另有 Summer 风格 `#[get]` 等短别名和 `#[route]` 多方法标记 | 一个 Controller 可声明完整 CRUD 路由；路径前缀只作用于该 Controller，长短名称语义相同 |
| R-MVC-02 | P0 | 宏生成显式可调用的 Router 装配入口；不要求每条方法手写 `Router::route` | 应用构造 Controller 后只需一次注册调用；可以与原生 Router 合并 |
| R-MVC-03 | P0 | 首版宏只处理结构体的固有 `impl` 及其方法；独立函数仍可通过原生 Axum Router 注册 | 单端点原生路由与 Controller 路由可以在同一应用运行 |
| R-MVC-04 | P0 | Controller 方法可使用 `&self`、Axum `Path`/`Query`/`State`/`Extension`、`IntoResponse`/`Result` 返回值；启用 `json` 后可使用 `BoundedJson`；认证与中间件仍可按 Router 分支设置 | 路径、查询、请求体和共享依赖的端到端测试通过 |
| R-MVC-05 | P0 | 宏对不支持的方法签名、非法路径、重复 HTTP 方法及 Controller 内重复路径+方法给出编译期诊断；跨 Controller 冲突在装配时明确失败 | `trybuild` 类编译失败测试及装配冲突测试覆盖 |
| R-MVC-06 | P0 | 声明式路由自动继承该 Router 分支的 body、并发、超时与诊断策略；路由可显式声明长连接类别 | 宏路由与手写路由对相同策略给出同样的拒绝/取消行为 |

宏的首版目标是 Rust 语境下的 Spring REST Controller 使用体验，不复制 Spring 的运行时反射、隐式依赖注入或参数注解全集。路径变量、查询参数和请求体由 Axum 提取器表达；`#[request_body]`、`#[path_variable]` 等逐参数属性别名和 OpenAPI 生成留待后续需求评审。首版支持显式 Controller 实例装配，避免通过全局注册表隐式构造有状态对象。

### 4.3 普通 HTTP 请求

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-HTTP-01 | P0 | 每个受保护路由有有限请求体字节上限；同时校验已声明长度与实际读取字节数 | 恰好达到上限可通过；超 1 字节及分块超限返回 413 |
| R-HTTP-02 | P0 | 短请求具备独立的在途并发限额与处理期限；过载立即拒绝，不形成无界队列 | 长连接占满自身额度时普通 API 仍可处理；容量拒绝为 503 |
| R-HTTP-03 | P0 | 对 SSE/WS 显式排除普通响应总时限，但保留各自的握手、空闲和关闭约束 | SSE 可超过普通请求期限持续发送；WS 不被短请求超时杀死 |
| R-HTTP-04 | P0 | 默认不启用 CORS、不信任代理转发头、不记录请求/响应体 | 无配置时跨源预检不获许可；日志无敏感载荷 |
| R-HTTP-05 | P0 | 与应用原生 Axum extractor 和 middleware 可组合；限额作用点和覆盖规则明确 | 路由级覆盖仅影响对应路由；应用层拒绝保留应用自己的响应 |

### 4.4 严格 JSON（`json` feature）

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-JSON-01 | P1 | 可选 `BoundedJson<T>` 按字节和结构预算严格解码，拒绝宽松修复 | 非法语法 400、不支持的 Content-Type 415、预算超限 413 |
| R-JSON-02 | P1 | JSON 解码与输出编码预算均为有限值，可按路由配置；输出须在完整编码成功后发送 | 输出预算失败不产生半个 JSON 响应；大整数保持精度 |
| R-JSON-03 | P1 | 普通 Axum `Json<T>` 继续可用；公共层的结构预算仅适用于显式选用的提取器/编码器 | 未选用时不声称受结构预算保护，HTTP 字节限制仍有效 |

### 4.5 SSE

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-SSE-01 | P0 | 应用使用 Axum `Sse` 定义事件；公共策略约束连接数、保活与关闭，不改写事件内容 | 事件按流逐项可见，保活不产生业务 ID |
| R-SSE-02 | P0 | 客户端断开或服务停止时向应用事件源传递取消；慢消费者不得导致无限缓存 | 测试能观察生产者退出，连接/任务/排队有界 |
| R-SSE-03 | P0 | SSE 不承担事件历史与重放；应用负责 `id`、`Last-Event-ID`、缺口和终态查询 | 文档及示例说明断线恢复属于应用协议 |

### 4.6 WebSocket（`ws` feature）

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-WS-01 | P1 | 升级前应用认证与可配置 Origin 规则可生效；浏览器携带 Origin 而未配置允许列表时拒绝 | 未授权和不允许 Origin 均不能建立 WS；非浏览器无 Origin 仍需应用认证 |
| R-WS-02 | P1 | 限制并发连接、单帧、完整消息、发送队列条数与总排队字节；队列满明确反馈背压 | 各边界均有独立测试；无静默丢弃、无无限每消息任务 |
| R-WS-03 | P1 | 支持 ping/pong、空闲检测、对端关闭与服务关闭信号；服务关闭尽力发送 close 帧 | 空闲/对端断开/全局关闭可观测且资源最终释放 |
| R-WS-04 | P1 | 应用可继续处理 Axum 原生文本/二进制消息；业务协议由应用控制 | 示例可实现自定义文本协议，无强制 JSON-RPC |

### 4.7 错误与诊断

| ID | 优先级 | 要求 | 验收条件 |
| --- | --- | --- | --- |
| R-ERR-01 | P0 | 启动/绑定/TLS/配置/运行/停止错误可由调用方按类别处理 | 错误类型与来源可识别；不把启动错误伪装为 HTTP 响应 |
| R-ERR-02 | P0 | 库生成的 HTTP 拒绝有稳定状态码和机器可读代码，业务错误保持应用定义 | 400/413/415/503 等矩阵可断言；原业务响应不被替换 |
| R-OBS-01 | P0 | 默认与 TRACE 诊断不含 Authorization、Cookie、敏感 query、body、Prompt、WS 消息、TLS 私钥 | 使用哨兵值的日志捕获测试无法找到明文 |
| R-OBS-02 | P0 | 能查询监听是否就绪及停止结果；业务依赖健康由应用汇总 | 监听成功后才报告 ready，业务数据库异常不被库误判 |

## 5. 默认配置与边界要求

以下数值是首版合同的**建议默认值**，实施前允许在设计评审中调整，但不能留作无界值。所有覆盖值必须为正，并在配置校验时检查相互关系；`0` 不能暗示无限制。

| 项目 | 默认值 | 覆盖方式与说明 |
| --- | --- | --- |
| HTTP 请求体 | 1 MiB | 路由可显式放宽；实际流量仍逐字节计数 |
| JSON 输入 / 输出字节 | 各 1 MiB | 输入不得超过所属 HTTP body 上限；输出编码先完整成功再发送 |
| JSON 深度 / 节点数 | 64 / 100,000 | 解码和编码都启用 |
| JSON 数组项 / 对象项 | 各 10,000 | 解码和编码都启用 |
| JSON key / string / number 字节 | 16 KiB / 256 KiB / 128 B | 针对单个值，另有总 payload 1 MiB 上限 |
| 普通请求在途数 | 256 | 服务级设置；过载立即 503 |
| 普通请求处理期限 | 30 秒 | 路由可显式覆盖；不适用于已升级或持续 SSE 响应 |
| SSE 并发连接 | 128 | 服务级或路由级收紧；超限 503 |
| SSE 保活间隔 | 15 秒 | 可配置；保活不携带业务 ID |
| WS 并发连接 | 128 | 服务级或路由级收紧；握手前拒绝 |
| WS 单帧 / 完整消息 | 64 KiB / 1 MiB | 分片重组后仍按消息限制 |
| WS 发送队列 | 64 条且 1 MiB | 两个上限同时满足；满时返回背压错误 |
| WS 握手期限 / 空闲期限 | 10 秒 / 60 秒 | 空闲判定含可观察的 ping/pong 状态 |
| 优雅关闭期限 | 30 秒 | 到期强制关闭剩余连接并报告数量 |

默认值用于常见 JSON API 与轻量流式状态，处理大文件、长时计算或高连接密度的应用须逐路由/服务调整；限额改变应由应用容量测试验证。SSE 事件源由应用自行选择有界通道或直接惰性流，库不能为任意应用 producer 的内存占用背书。

## 6. 状态、错误与取消合同

| 事件 | 对客户端/应用的结果 |
| --- | --- |
| HTTP 请求超字节预算 | 413；尽量停止继续读取；不保证客户端已收到完整响应后才关闭连接 |
| JSON 语法或目标类型不匹配 | 400；机器码区分语法与反序列化失败 |
| JSON Content-Type 不受支持 | 415 |
| HTTP 短请求或 SSE/WS 配额满 | 503；握手不得升级 |
| WS 帧/消息越限 | 协议 close（适用时使用 1009），释放连接；若发生于升级前则拒绝握手 |
| WS 发送队列满 | 发送操作返回可识别背压错误；应用决定重试、合并或关闭 |
| 客户端断开 SSE/WS | 会话取消通知触发；库不替应用取消已受理业务任务 |
| 宿主 shutdown | 停止接收新连接，通知长连接，等待至期限；返回含强制终止信息的报告 |

库自己的 HTTP 拒绝可使用小型 `application/problem+json` 响应，至少含稳定 `type`/`code`/`title`，不得反射原始请求内容。是否暴露 `request_id` 由应用或诊断层决定。错误状态码与机器码须在后续兼容版本中稳定维护。

## 7. 验收与交付

### 7.1 必须覆盖的验收场景

1. MVC/HTTP：Controller CRUD 宏、原生 Router/State/middleware、404、编译期非法写法、路由冲突、端口 0、绑定冲突、全局与路由级大小边界、chunked 超限、短请求并发与超时。
2. HTTPS：有效证书握手、证书错误、同一路由 WSS、明文误连；测试证书只在测试环境使用。
3. JSON：Content-Type、严格语法、深度/节点/字符串/数值/总输入预算、输出预算、大整数精度。
4. SSE：逐项交付、保活、断开取消、慢读者、配额与普通请求并发、shutdown。
5. WS：认证与 Origin、帧/消息及队列各边界、背压、ping/pong、空闲、对端关闭、shutdown。
6. 隐私：默认与 TRACE 日志哨兵测试；敏感内容不能通过错误 Display/Debug 泄漏。
7. 兼容：默认、`json`、`ws`、`tls-rustls`、全 feature 分别构建/测试；Rustdoc、格式与 rs-infra 检查通过。

### 7.2 交付物与完成定义

- 公开 API、宏 Rustdoc 和两个可运行示例：Prompt/Agent 风格 HTTP+SSE+WS 示例与使用 REST Controller 宏的非 Agent JSON CRUD 示例。Prompt 示例仅模拟传输，不宣称真实 Agent 或持久化。
- 所有 P0 要求及已发布的 P1 feature 通过验收；限额真实生效，退出无遗留任务。
- feature 关闭时不会引入相应可选依赖；`cargo test --all-features` 与仓库 CI 通过。
- 产品接入、部署证书和业务端到端合同由消费项目单独验证。

## 8. 分阶段交付与追踪

| 阶段 | 对应需求 | 可交付结果 |
| --- | --- | --- |
| A HTTP 运行层 | R-SRV-01/02/04/05、R-ERR-01 | 可绑定、可请求、可停止的最小服务 |
| A2 声明式 REST | R-MVC-* | 结构体及 `impl` 方法宏、显式装配、编译期诊断和 CRUD 示例 |
| B HTTPS | R-SRV-03 | 同 Router 的 HTTPS/WSS 和 TLS 错误前置校验 |
| C 限额与诊断 | R-HTTP-*、R-ERR-02、R-OBS-* | 有界短请求和默认安全日志 |
| D JSON 与流式连接 | R-JSON-*、R-SSE-*、R-WS-* | 严格 JSON、SSE/WS 生命周期与背压 |
| E 消费者验证 | G4 与全部验收 | 两类示例、feature matrix、Rustdoc/CI |

## 9. 已明确的产品决策

采用独立服务端库，默认提供 REST Controller 属性宏并保留 Axum 原生 Router；直接 HTTPS 通过可选 rustls feature 提供；SSE 作为 HTTP 流式响应；没有默认业务重试、事件重放或 IoC。具体依赖版本、实现结构和可编译 API 以详细设计与实施验证为准；PRD 的行为边界与验收 ID 是变更评审基准。
