# rs-web 期限溢出、历史文档状态与响应体源码组织设计

> 状态：待实施设计。依据 2026-10-13 的重新评审及用户已接受的三项意见编写；本文不表示源码已修复。实施步骤见 [同轮计划](implementation-plan-20261013T095931709Z-31b89cb3.md)。

## 背景与现状

1. `HttpLimits::with_request_timeout` 仅拒绝零值；`RequestLimitLayer` 随后执行 `tokio::time::Instant::now() + request_timeout`。`ServerOptions::validate` 同样只检查停服期限非零；`ServerContext::begin_shutdown` 执行 `Instant::now() + shutdown_timeout`。`Duration::MAX` 这类正数可通过配置校验，却会在加法处 panic。`Ws` 的 `get_close_deadline` 还有一个对停服期限执行同类加法的兜底路径。
2. `f3dab76` 已实现短响应超时主动丢弃应用 body 和归还许可；`1bd017a` 已同步 README、用户指南和现行架构摘要。但 `doc/design-20261013T073858154Z-7cc1c7fc.md` 与对应实施计划顶部仍称该功能待实施，正文仍以修复前行为叙述。
3. `src/limit/internal/permit_body.rs` 同时定义 `Phase`、`BodyState`、`PermitBody`。这与项目 Rust 风格规则 ORG-001 的生产类型独立文件约定不符；三个类型均为当前响应体生命周期实现的私有细节。

现有容量域、响应头后只能报告 body error、受管会话统计和下游 `rs-websocket` 固定旧 Git revision 的合同均不因本方案改变。

## 目标与验收合同

- 无法由当前 Tokio 单调时钟表示为绝对截止时间的请求期限、停服期限，应在配置阶段返回既有的 `WebServerError::InvalidConfig`；配置对象在稍后的运行阶段仍必须有无 panic 的兜底路径。
- 若请求运行时才发现截止时间不可表示，释放本次取得的短请求许可，返回稳定的 HTTP 500 `application/problem+json`，代码为 `invalid_configuration`；不得将其误报成客户端请求超时。若停服运行时才发现，立即关闭新会话接纳、发出取消通知、终止并回收连接任务，然后由 `serve` 返回 `WebServerError::InvalidConfig`。
- `Duration::ZERO` 的原有拒绝行为、正常期限的起点与 HTTP 504/响应体超时行为保持不变。绝对期限只计算一次，继续同时约束 handler 与响应体。
- 两份 2026-10-13 短响应历史方案在顶部清楚标为“已实施”，保留原正文作为当时决策记录，并说明其中“当前”“待实施”均指写作时状态；文档索引能引导读者优先阅读现行使用合同。
- `Phase`、`BodyState`、`PermitBody` 分居 `internal/` 下独立文件。拆分不改变可观察行为、公共 API、资源释放顺序或测试边界。

## 方案选择

| 方案 | 优点 | 不足 | 决定 |
| --- | --- | --- | --- |
| 给所有期限规定任意固定上限，例如一年 | 校验容易 | 限制了本可表示的较长期限；平台时钟仍需兜底 | 不采用 |
| 仅在配置时用 `checked_add` | 拒绝通常的溢出输入 | 从配置到使用期间时钟继续前进，边界值仍可能溢出 | 不采用 |
| 配置时及实际计算时均用 `checked_add`，分别返回明确错误 | 不引入任意期限上限；运行阶段无 panic | 极端运行时失败需定义错误与清理路径 | **采用** |
| 溢出时静默改成无限期或立即到期 | 无新增错误 | 改变用户配置语义，可能导致资源长期占用或意外停服 | 不采用 |

`checked_add` 的判断依赖当前单调时钟，因此不宣称某个 `Duration` 在所有未来时刻永久有效。配置阶段尽早拒绝；运行阶段的检查是最终保障。无需新依赖或公共 `Deadline` 类型。

## 代码结构与数据流

### 请求期限

- `HttpLimits::with_request_timeout(timeout)` 保持现有 `Result<Self, WebServerError>` 签名。零值或 `tokio::time::Instant::now().checked_add(timeout).is_none()` 返回 `InvalidConfig`。文档的 `# Errors` 同步列出两种原因。
- `enforce_limits` 在取得许可后，用 `checked_add` 计算 `deadline_at`。若为 `None`，局部许可随返回立即释放，返回新增 `WebRejection::InvalidConfiguration`：HTTP 500、代码 `invalid_configuration`、标题 `Internal Server Error`。响应不包含原始配置值。
- 成功时仍将同一个 `deadline_at` 传给 `tokio::time::timeout_at` 与 `permit_body`。不得重新实现或改动现有 `PermitBody` 超时看守逻辑。

### 停服期限

- `ServerOptions::validate` 检查 `shutdown_timeout` 非零且可与当前 `Instant` 相加。其余请求头与传输空闲期限维持当前校验合同，本轮只处理已核实的绝对加法路径。
- `ServerContext::begin_shutdown` 改成 `Result<Instant, WebServerError>`。若共享状态已有截止时间，直接复用该值并保持关闭接纳与取消的幂等调用，不重新计算。首次调用时尝试 `checked_add`；失败则使用 `now` 作为内部立即截止时间写入共享状态，但仍执行 `sessions.begin_shutdown()` 和 cancellation，最后返回 `InvalidConfig`。成功时记录并返回正常期限。这样即使极端时钟边界在 bind 与 shutdown 之间发生，也不会跳过停服信号。
- `WebServer::serve` 遇到 `begin_shutdown` 的错误时，停止接纳、`abort_all` 并 drain `JoinSet`，最后返回该错误；不要返回貌似正常的 `ShutdownReport`。正常期限继续走原有 graceful/强制关闭逻辑。
- `ws::internal::close::get_close_deadline` 的 fallback 改为 `Instant::now().checked_add(timeout).unwrap_or(now)`。它仅作为关闭时的防 panic 兜底：无法表示时立即到期，不延长关闭；已有共享 server deadline 仍优先。更新其 Rustdoc，不能继续声称只有内部 invariant 才可能 panic。

新增 `WebRejection` 变体和 `ServerContext::begin_shutdown` 的 crate 内签名变化允许破坏性变更。公共 `HttpLimits`、`ServerOptions` 方法签名保持现状。使用者若对 `WebRejection` 穷尽匹配，需要处理新变体。

### 源码组织

将 `Phase` 移入 `src/limit/internal/phase.rs`，将 `BodyState` 移入 `src/limit/internal/body_state.rs`，`PermitBody` 及其 `HttpBody`/`Drop` 实现、`watch_deadline` 与 `permit_body` 保留在 `permit_body.rs`。在 `src/limit/internal.rs` 声明两个新子模块。只给跨兄弟模块所需的类型和字段最小的 `pub(super)` 可见性，不向 crate 外导出；保留原 Rustdoc 语义和全部阶段转移。此拆分不授权顺手重写状态机或其他文件的类型布局。

## 测试与文档

- `tests/http_limits_tests.rs`：断言 `Duration::MAX` 被 `with_request_timeout` 拒绝；保留并运行未轮询响应体、单次超时错误、正常 EOF、提前 Drop 与容量归还测试。`WebRejection` 稳定响应测试增加 `InvalidConfiguration` 的 500 与代码。
- `tests/shutdown_tests.rs` 或 `src/server/server_context.rs` 必要的私有单元测试：覆盖 `Duration::MAX` 的 `ServerOptions::validate` 拒绝、`begin_shutdown` 溢出时仍关闭登记与取消、`serve` 清理路径。测试应在公开边界能观察时优先放 `tests/`，不为测试增加生产接口。
- `ws::internal::close` 的私有单元测试覆盖 fallback 的 `Duration::MAX` 不 panic 且返回不晚于调用后的 `Instant::now()`；正常共享截止时间优先级保持。
- 更新受影响的 Rustdoc、中英文 README、用户指南、现行中英文架构摘要，仅说明新增极端期限校验和 HTTP 500 兜底。两份旧设计文件只加顶部历史状态说明；`doc/README.md` 把本轮设计和计划列入历史/实施记录，继续指向现行双语指南。中英文数值、错误码和条件须一致。
- `rs-websocket` 的互操作测试仍固定旧 rs-web revision；它可作使用案例，不能证明本次 HEAD 兼容。无需修改下游仓库。

## 实施风险与边界

`begin_shutdown` 的错误路径必须先取消并回收连接，避免把防 panic 修复变成泄漏；`WebRejection` 新变体须同步其 `status`、`code`、`IntoResponse` 和测试。拆分状态类型后须核对锁外析构/唤醒及 watcher 取消顺序。此次设计不修改 TLS、JSON、Controller、SSE 或 WebSocket 策略的其他配置规则；若实施时发现另一条实际可由合法公开配置触发的同类加法，再以具体证据扩充测试与设计，而非批量重构。
