# rs-web 短响应期限与文档状态修复设计

> **历史状态：已实施。** `f3dab76` 实现短响应期限清理，`1bd017a` 同步使用文档。下文的“当前”“待实施”均指本文件写作时的状态记录；现行合同以双语用户指南和架构摘要为准。

> 日期：2026-10-13。本文件记录当时提出的设计方案，依据该轮评审的两项已接受意见制定。

## 背景与证据

`RequestLimitLayer` 为短请求取得并发许可，并用同一个绝对期限限制 handler 与响应体。当前 `PermitBody` 仅在 `poll_frame` 中轮询 `Sleep` 和释放许可。客户端停止读取、HTTP/2 流量窗口耗尽或传输背压使 Hyper 不再轮询响应体时，期限虽已过去，响应体生产者及许可仍可能保留。`tests/http_limits_tests.rs::response_body_deadline_releases_short_request_capacity` 持续轮询响应体，因此没有覆盖这个边界。`WebServer` 的传输空闲检测把尚未结束的响应体视为活跃，也不能替代短请求期限。

本地未跟踪的 `doc/design-20261013T043730450Z-e89680a2.md` 和 `doc/implementation-plan-20261013T043730450Z-e89680a2.md` 仍称 WebSocket 最终值校验、Controller 增量预检待实施；对应代码与测试已存在。这两份文件不在正式文档索引中，但留在工作目录会误导后续执行者。

## 目标与边界

1. 短响应到达绝对期限时，即使响应体从未再次被轮询，也主动丢弃应用响应体并归还短请求并发许可。期限仍从取得许可后、开始处理请求时计算，覆盖 handler 和响应体。
2. 已发送响应头后的期限到达不能改写 HTTP 状态；若传输再次轮询响应体，返回一次超时 body error，然后结束。响应头发出前的 handler 超时继续返回现有 `504`。请求体超限和容量不足的现有响应不变。
3. 正常 EOF、body error、调用方丢弃响应体和超时之间只允许一次资源释放。超时后不能再轮询应用响应体或产出新的应用数据帧。
4. 将两份较早的本地未跟踪方案明确标为已实施的历史记录，并记录实施提交；不删除文件，不修改历史设计内容与结论。
5. 只改动上述边界所需的 `limit` 实现、测试、Rustdoc、双语使用文档和这两份历史方案。SSE、WebSocket、Controller 路由、TLS 与下游仓库保持现有行为。无需破坏公共 API；若实现中发现必要的破坏性变更，本任务允许，但必须在实施时记录原因并同步双语文档。

## 方案比较

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 继续在 `poll_frame` 内检查期限 | 代码少 | 背压停止轮询时不能回收许可 | 不采用 |
| 到期后取消整个 HTTP 连接 | 可强制传输退出 | HTTP/2 中一个超时流会中断同连接的其他流；与独立 `RequestLimitLayer` 用法耦合 | 不采用 |
| 为每个非空短响应设置到期看守任务，共享一个可终止的 body/许可状态 | 不依赖传输轮询即可丢弃生产者和归还许可；不牵连其他流 | 每个在途响应多一个轻量任务，需严格处理竞争与取消 | 采用 |
| 只在到期时归还许可，等待下一次轮询才丢弃 body | 易实现 | 已过期的生产者仍被保留，资源生命周期不清晰 | 不采用 |

## 内部结构与生命周期

把 `src/limit/internal/permit_body.rs` 的内部响应包装器改为“共享状态 + 到期看守任务”。共享状态由 `Arc<Mutex<...>>` 持有，包括应用 `Body`、`OwnedSemaphorePermit`、阶段和最近一次待唤醒的 `Waker`。阶段至少区分 `Active`、`TimedOut`、`Finished`；公开函数 `permit_body(inner, permit, deadline) -> Body` 的签名不变。每个非空响应体启动一个 Tokio 任务，`sleep_until(deadline)` 后在互斥锁内把 `Active` 转为 `TimedOut`，取走应用 body 和许可；锁外先丢弃 body，再归还许可，最后唤醒保存的 waker。任务在状态不再活跃时直接退出。短响应的最大并发数已有上界，故看守任务数量受该上界约束。

包装器的 `poll_frame` 在同一互斥锁下检查状态及当前绝对时间，再轮询应用 body。持锁期间仅调用同步的 `poll_frame`，不执行 `.await`；释放锁后才丢弃被取出的 body、许可或唤醒 waker。若 `Active` 且尚未到期，正常转发帧；`Pending` 时登记 waker。若本次轮询发现期限已过，执行与看守任务相同的转移并返回一次超时错误。若看守任务已先转成 `TimedOut`，本次轮询只返回一次超时错误；再次轮询返回 `None`。正常 EOF、body error、`Drop` 都转为 `Finished` 并释放资源，同时取消看守任务。`is_end_stream` 在尚未交付超时错误的 `TimedOut` 阶段返回 `false`，交付后返回 `true`；`size_hint` 在超时或完成后为空。已有 `Body` 的错误类型仍转换为 `axum::Error`。

状态转移由同一把锁裁决竞争，避免超时任务与轮询或 `Drop` 双重释放。期限边界按取得锁时的 `tokio::time::Instant::now()` 判断：已经由较早一次轮询产生的帧可正常返回，期限之后不会再次轮询应用 body。`Drop` 必须在调用线程同步取走并释放 body 与许可，再取消尚未结束的看守任务，不能把许可归还延迟到异步任务被调度；任务持有的 `Arc` 不得形成永久引用环。沿用项目对互斥锁中毒的处理方式，不能因中毒使许可永久滞留。互斥锁中的 `Body` 可以同步轮询，因为现有实现已经将其作为可 `Pin::new` 的 `Body` 使用；实施时以编译器和测试验证 `Send`、`Unpin` 等约束。

这是**应用响应体与短请求许可**的主动终止合同。HTTP 响应头已发出且传输永不再轮询时，包装器无法单独强制底层 HTTP/2 流立即向客户端报告错误，也不承诺关闭整个连接；传输连接仍由独立的 `WebServer` 上限和宿主网络策略管理。双语文档要明确这一区别，避免把“许可按时归还”写成“客户端必在该时刻收到超时状态”。

## 测试合同

- 新增不轮询首个响应体的回归：把短请求并发设为 1、期限设为短正值；取得一个永不结束的响应后保持其 body 不被轮询；到期后，同一 `RequestLimitLayer` 的第二请求必须获准。使用可观察 `Drop` 标记证明首个应用 body 已被丢弃；随后第一次轮询旧响应体得到超时错误，第二次得到 `None`。
- 保留现有持续轮询的超时测试，覆盖 waker 唤醒路径；保留正常 EOF、body error、提前丢弃响应体的容量归还测试，并增加到期与提前丢弃相邻时序的单次释放断言。
- 增加真实 `WebServer` 网络测试：客户端读取响应头后停止读取足以产生背压的流式 body，等待期限后从另一连接请求同一限额域中的短路由，应能成功。测试必须有外层超时并在结束时关闭连接和服务；不以操作系统缓冲区的固定大小作为断言。若网络测试在平台上无法稳定制造背压，保留确定性的未轮询 body 回归作为必须门禁，并明确记录网络测试的环境限制。
- 在中英文 README、用户指南和现行中英文架构设计摘要中，只更新受此合同影响的短请求期限段落。Rustdoc 更新 `RequestLimitLayer`、`HttpLimits::with_request_timeout` 与内部 `PermitBody` 的语义；中英文含义一致。

## 验收与风险

验收以未轮询 body 的许可归还和生产者 `Drop` 为核心，而非仅看完整测试通过。验证包括聚焦测试、`cargo test --workspace --all-features --offline`、默认 feature 测试、Rustdoc、`cargo fmt --all -- --check`、Clippy 和仓库现有风格门禁。下游 `rs-websocket` 固定较旧 rs-web revision，仅作为用法参照，不作为当前提交兼容性证明。

主要风险是超时、轮询、提前丢弃同时发生时的资源释放顺序和 waker 竞争；上述阶段状态与单锁转移用于约束该风险。响应头之后的 body error 与以前一致，但客户端在传输背压下看到该错误的时刻依赖 Hyper 与网络，不作为期限保证。看守任务的数量及生命周期必须由容量测试与早终止测试验证，不能留下 detached 的长期任务。
